PAM — MySQL + phpMyAdmin + API sync (localhost)
================================================================================

1) Co jest gdzie
   - Android Room (SQLite) = lokalna baza w aplikacji (offline).
   - MySQL (Docker) = serwerowa baza do podglądu w phpMyAdmin i dalszego backendu.
   - API (Node.js, port 8090) = most Room -> MySQL (upload rekordów).

2) Start środowiska Docker
   - Zainstaluj Docker Desktop (Windows).
   - PowerShell / CMD:
       cd C:\Users\Lumis\StudioProjects\PAM\database
       docker compose up -d --build
   - Poczekaj ~30–60 s na pierwszy start.
   - phpMyAdmin: http://localhost:8080
   - API health: http://localhost:8090/health
   - Logowanie phpMyAdmin:
       Serwer: (zostaw domyślny / mysql)
       Użytkownik: root
       Hasło: pam_root_dev
   - Aby wyczyścić wolumen i postawić od zera:
       docker compose down -v
       docker compose up -d --build

3) Tabele i przeznaczenie (schema v2)
   - users
     profil użytkownika (username, email, display_name, is_active).
   - user_credentials
     dane logowania (hash hasła i algorytm), 1:1 z users.
   - auth_sessions
     sesje/refresh tokeny (device, expires_at, revoked_at).
   - vehicles
     pojazdy przypisane do użytkownika.
   - measurement_attempts
     rekordy pomiarów (client_record_id, typ, czas, dystans, vmax),
     opcjonalnie powiązane z users/vehicles.
   - sync_events
     dziennik zdarzeń synchronizacji backendu.

4) Upload automatyczny rekordów z aplikacji
   - Każdy nowy pomiar zapisuje się najpierw w Room z sync_state='pending'.
   - WorkManager automatycznie odpala worker synchronizacji.
   - Worker wysyła rekord(y) do POST /api/attempts.
   - Backend robi UPSERT po client_record_id (brak duplikatów).
   - Gdy upload się nie uda: rekord zostaje lokalnie jako failed i jest ponawiany.

5) Jak sprawdzić, czy upload działa
   - Logcat: tag "MeasurementSync".
   - phpMyAdmin:
       baza pam -> measurement_attempts (nowe rekordy)
       baza pam -> sync_events (slad insert/update/error)
   - API test:
       GET http://localhost:8090/health

6) Jeśli rekordy nie wpadają do MySQL
   - Sprawdź, czy kontener API działa:
       docker compose ps
       docker compose logs api
   - Emulator Android:
       BuildConfig.SYNC_BASE_URL = "http://10.0.2.2:8090/"
   - Telefon fizyczny:
       ustaw SYNC_BASE_URL = "http://TWOJE_IP_LAN:8090/"
       i dodaj IP do network_security_config.xml (lub użyj HTTPS).
   - Jeśli masz stary wolumen MySQL:
       uruchom ręcznie SQL z database/mysql/03_upgrade_existing.sql

7) Bezpieczeństwo
   - Hasła w docker-compose.yml są TYLKO na lokalny development.
   - Nie commituj produkcyjnych haseł; na serwerze użyj zmiennych środowiskowych.
